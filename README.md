# 텔레그램 자동 입장 (Telegram auto-join)

여러 개의 텔레그램 계정으로 홍보방·소통방에 순차 입장하고, 입장한 방이 소개하는 다른 방의 링크를 모아 다시 입장 후보로 올리는 관리 도구입니다.

핵심은 **속도가 아니라 페이싱**입니다. 텔레그램은 짧은 시간에 여러 방에 들어가는 계정에 대기시간(FloodWait)을 요구하는데, 이 도구는 그것을 오류가 아니라 정상적인 신호로 다룹니다. 계정별로 간격을 두고 한 번에 하나씩 입장하고, 대기 요구를 받으면 그 계정만 멈췄다가 시간이 지나면 스스로 재개합니다.

---

## 무엇을 하는가

| 기능 | 설명 |
| --- | --- |
| **입장 큐** | 선택한 방들을 계정에 배정해 큐에 넣고, 워커가 계정별 간격에 맞춰 하나씩 처리합니다. |
| **대기시간 처리** | `FLOOD_WAIT` 를 받으면 해당 계정을 `COOLDOWN` 으로 두고 재개 시각을 기록합니다. 다른 계정은 계속 돕니다. |
| **선행 채널 자동 인식** | "먼저 아래 채널에 가입하세요" 안내를 읽어 요구된 채널을 큐 앞쪽에 넣고, 그 방들에 먼저 입장한 뒤 원래 방을 다시 처리합니다. 인식한 선행 관계는 저장되어 다음 작업부터 처음부터 반영됩니다. |
| **숨은 선행 채널 탐색** | 읽어서는 알 수 없는 방에 한해 짧은 인사말을 한 번 보내 반응을 보고, 보낸 메시지는 즉시 삭제합니다. 방마다 한 번만. |
| **홍보 링크 수집** | 입장해 있는 방을 몇 시간 간격으로 훑어 다른 방의 초대 링크를 모으고, 텔레그램에 실체를 확인한 뒤 0–100 점으로 채점합니다. |
| **자동 등록·연쇄 수집** | 기준 점수를 넘는 링크를 그룹으로 자동 등록하고, 선택하면 입장까지 예약합니다. 하루 등록 한도가 유일한 제동장치입니다. |

## 빠르게 실행하기

```bash
npm install
cp .env.example .env          # SESSION_SECRET 을 임의의 긴 문자열로 바꾸세요
npm run setup                 # prisma generate + db push + 예시 데이터
```

터미널 두 개로 앱과 워커를 함께 띄웁니다. **워커가 돌지 않으면 큐는 영원히 대기 상태입니다.**

```bash
# 터미널 1 — 웹
MOCK_TELEGRAM=1 npm run dev

# 터미널 2 — 워커
MOCK_TELEGRAM=1 npm run worker
```

`MOCK_TELEGRAM=1` 은 실제 텔레그램에 접속하지 않는 테스트 모드입니다. 가짜 방·가짜 선행 채널·가짜 대기시간이 결정론적으로 생성되므로, 계정 없이도 큐·페이싱·수집이 도는 것을 그대로 볼 수 있습니다.

### 실제 계정 연결

1. <https://my.telegram.org> → *API development tools* 에서 `api_id` / `api_hash` 를 발급받아 `.env` 에 채웁니다.
2. `MOCK_TELEGRAM=0` 으로 앱과 워커를 다시 띄웁니다.
3. **계정** 화면 → *계정 연결* → 전화번호 입력 → 문자로 온 코드 입력 (2단계 인증이 걸려 있으면 비밀번호까지).

기존에 발급받은 StringSession 이 있다면 *세션 문자열 붙여넣기* 로 바로 등록할 수도 있습니다.

## 화면

| 경로 | 내용 |
| --- | --- |
| `/` | 오늘 입장 수, 대기 중 작업, 대기시간이 걸린 계정, 진행 중인 작업, 최근 입장 기록 |

| `/collected` | 수집된 링크 검토·승인·등록, 수집 정책 |
| `/accounts` | 계정 연결, 페이싱 간격, 일일 한도, 대기 해제 |

## 구조

```
src/
  lib/
    telegram/         MTProto 계층 — 인터페이스 하나에 실제/모의 구현 둘
      types.ts          TelegramSession 인터페이스, 오류 코드
      real.ts           teleproto(GramJS 포크) 구현
      mock.ts           MOCK_TELEGRAM=1 용 가짜 텔레그램
      errors.ts         서버 오류 문자열 → 내부 오류 코드
      login.ts          전화번호 → 코드 → 2FA 로그인 대화
      crypto.ts         세션 문자열 AES-256-GCM 암호화
    services/         DB 위의 도메인 로직 (UI·워커 공용)
    links.ts          t.me 링크 파싱·정규화
    scoring.ts        수집 링크 0–100 채점
    prerequisites.ts  선행 채널 안내문 인식
  worker/
    main.ts           틱 루프
    joinRunner.ts     작업 1건 실행 — 입장, 선행 채널, 오류 분류
    collector.ts      방 순회 수집, 링크 실체 확인, 자동 등록
  app/                Next.js App Router (서버 컴포넌트 + 라우트 핸들러)
```

**워커와 웹은 별개 프로세스**이고 SQLite 를 통해서만 통신합니다. 웹은 큐에 넣기만 하고, 텔레그램에 말을 거는 것은 워커뿐입니다 (계정 로그인만 예외 — 대화형이라 웹이 직접 처리합니다).

### 한 번의 틱

```
계정마다:
  대기 중인가?         → 건너뜀 (재개 시각이 지나면 자동 해제)
  간격이 찼는가?        → 아니면 건너뜀
  일일 한도를 넘었나?    → 넘었으면 건너뜀
  → 다음 작업 1건 실행 (선행 채널이 우선순위 앞)
그다음:
  방 몇 개 순회 수집 → 미확인 링크 실체 확인 → 채점 → 기준 넘으면 자동 등록
```

계정 안에서는 철저히 순차, 계정끼리는 병렬입니다.

### 오류를 다루는 방식

| 상황 | 처리 |
| --- | --- |
| `FLOOD_WAIT` | 계정 전체를 요구된 시간만큼 정지. 작업은 그 시각으로 재예약되고 시도 횟수는 늘지 않음 |
| 이미 참여 중 / 승인 대기 | 실패가 아님 — 각각 `SUCCESS`, `WAITING_APPROVAL` 로 기록 |
| 링크 만료·비공개·차단 | 영구 실패로 즉시 중단 |
| 네트워크·분류 불가 | 30초 → 2분 → 10분 백오프 후 재시도, 3회 초과 시 실패 |
| 세션 만료 | 계정을 `NEEDS_CHECK` 로 두고 재연결을 요구 |

## 안전장치

이 도구는 남의 방에 계정을 밀어 넣는 일을 하므로, 기본값은 전부 보수적으로 잡혀 있습니다.

- **입장 간격 기본 20초.** 5초 미만은 입력 자체가 거부됩니다.
- **대기 요구는 그대로 따릅니다.** 우회하거나 다른 계정으로 같은 방을 다시 두드리지 않습니다.
- **말 걸기는 방마다 한 번.** 보낸 메시지는 즉시 삭제합니다. 기본값은 꺼져 있습니다.
- **연쇄 수집의 유일한 제동장치는 하루 등록 한도**입니다. 켜기 전에 한도를 낮게 잡으세요.
- **세션 문자열은 암호화 저장**됩니다. `SESSION_SECRET` 을 바꾸면 기존 세션은 복호화되지 않습니다.

## 개발

```bash
npm run test        # 링크 파싱·채점·선행 채널 인식 단위 테스트
npm run typecheck
npm run worker:once # 틱 한 번만 실행 (cron 이나 디버깅용)
npm run db:studio   # Prisma Studio 로 DB 열기
```

기본 DB 는 SQLite (`prisma/dev.db`) 입니다. Postgres 로 옮기려면 `prisma/schema.prisma` 의 `datasource` 를 바꾸고 `prisma db push` 를 다시 실행하면 됩니다. 스키마는 SQLite 에 맞춰 열거형 대신 문자열, 배열 대신 쉼표 구분 문자열을 씁니다 (허용값은 `src/lib/enums.ts`).

### 환경 변수

| 변수 | 기본값 | 설명 |
| --- | --- | --- |
| `DATABASE_URL` | `file:./dev.db` | Prisma 연결 문자열 |
| `TELEGRAM_API_ID` / `TELEGRAM_API_HASH` | — | my.telegram.org 발급 값. 실제 모드에서 필수 |
| `SESSION_SECRET` | — | 세션 암호화 키. 32자 이상 임의 문자열 |
| `MOCK_TELEGRAM` | `0` | `1` 이면 가짜 텔레그램으로 동작 |
| `WORKER_TICK_SECONDS` | `5` | 워커 틱 간격 |
