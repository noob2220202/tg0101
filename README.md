# 텔레그램 자동 입장 (Telegram auto-join)

여러 개의 텔레그램 계정으로 홍보방·소통방에 순차 입장하고, 입장한 방이 소개하는 다른 방의 링크를 모아 다시 입장 후보로 올리는 관리 도구입니다.

핵심은 **속도가 아니라 페이싱**입니다. 텔레그램은 짧은 시간에 여러 방에 들어가는 계정에 대기시간(FloodWait)을 요구하는데, 이 도구는 그것을 오류가 아니라 정상적인 신호로 다룹니다. 계정별로 간격을 두고 한 번에 하나씩 입장하고, 대기 요구를 받으면 그 계정만 멈췄다가 시간이 지나면 스스로 재개합니다.

---

## 무엇을 하는가

| 기능 | 설명 |
| --- | --- |
| **입장 큐** | 선택한 방들을 계정에 배정해 큐에 넣고, 워커가 계정별 간격에 맞춰 하나씩 처리합니다. |
| **대기시간 처리** | `FLOOD_WAIT` 를 받으면 해당 계정을 `COOLDOWN` 으로 두고 재개 시각을 기록합니다. 다른 계정은 계속 돕니다. |
| **선행 채널 자동 인식** | "먼저 아래 채널에 가입하세요" 안내를 읽어 요구된 채널을 큐 앞쪽에 넣고, 그 방들에 먼저 입장한 뒤 원래 방을 다시 처리합니다. 인식한 선행 관계는 저장되어 다음 작업부터 처음부터 반영됩니다. |
| **숨은 선행 채널 탐색** | 읽어서는 알 수 없는 방에 한해 짧은 인사말을 한 번 보내 반응을 보고, 보낸 메시지는 즉시 삭제합니다. 방마다 한 번만. |
| **홍보 링크 수집** | 입장해 있는 방을 몇 시간 간격으로 훑어 다른 방의 초대 링크를 모으고, 텔레그램에 실체를 확인한 뒤 0–100 점으로 채점합니다. |
| **자동 등록·연쇄 수집** | 기준 점수를 넘는 링크를 그룹으로 자동 등록하고, 선택하면 입장까지 예약합니다. 하루 등록 한도가 유일한 제동장치입니다. |
| **웹 채팅** | 연결된 계정의 대화를 웹에서 그대로 주고받습니다. 계정 전환, 실시간 수신, 미디어, 읽음 처리. |
| **프로필 관리** | 이름·소개·아이디·프로필 사진을 웹에서 변경하고, 활성 세션을 확인·종료합니다. |
| **키워드 알림** | 입장해 있는 모든 방의 새 메시지를 검사해 지정 단어가 뜨면 알립니다. 적중한 메시지만 보관합니다. |
| **계정 건강도** | @SpamBot 자동 조회로 스팸 제한을 감지하고, 페이싱·입장량·대기 요구를 합산해 0–100 위험도를 냅니다. |
| **1인용** | 로그인이 없습니다. 방화벽이나 SSH 터널 뒤에서 혼자 쓰는 것을 전제로 합니다. |

## 빠르게 실행하기

```bash
npm install
cp .env.example .env          # SESSION_SECRET 을 임의의 긴 문자열로 바꾸세요
npm run setup                 # prisma generate + db push + 예시 데이터
```

터미널 두 개로 앱과 워커를 함께 띄웁니다. **워커가 돌지 않으면 큐는 영원히 대기 상태입니다.**

```bash
# 터미널 1 — 웹
MOCK_TELEGRAM=1 npm run dev

# 터미널 2 — 워커 (+ 게이트웨이)
MOCK_TELEGRAM=1 npm run worker
```

다른 포트로 띄우려면 `-- -p 4001` 을 붙입니다 (`npm run dev -- -p 4001`). 워커의 게이트웨이는 별도 포트(기본 4599)라 웹 포트와 겹치지 않습니다.

브라우저에서 <http://localhost:3000> 을 열면 바로 대시보드가 뜹니다. 로그인 화면은 없습니다.

> **채팅은 워커가 떠 있어야 동작합니다.** 텔레그램 세션은 워커 프로세스만 들고 있고, 웹은 그 안의 게이트웨이를 통해서만 텔레그램에 접근합니다.

`MOCK_TELEGRAM=1` 은 실제 텔레그램에 접속하지 않는 테스트 모드입니다. 가짜 방·가짜 선행 채널·가짜 대기시간이 결정론적으로 생성되므로, 계정 없이도 큐·페이싱·수집이 도는 것을 그대로 볼 수 있습니다.

## 실전으로 띄우기 (시드 데이터 없이)

`npm run setup` 은 예시 계정·방을 만듭니다. 실제로 운영할 때는 **`setup:prod`** 를 쓰세요 — 스키마만 만들고 데이터는 넣지 않습니다.

```bash
git clone https://github.com/noob2220202/tg0101.git
cd tg0101
git checkout claude/telegram-auto-join-saas-e6nq8j
npm ci

cp .env.example .env
#   아래 4개는 반드시 채우거나 바꿔야 합니다.
#   TELEGRAM_API_ID / TELEGRAM_API_HASH  — my.telegram.org 발급값
#   SESSION_SECRET                        — openssl rand -base64 32
#   GATEWAY_TOKEN                         — openssl rand -base64 24
#   MOCK_TELEGRAM="0"

npm run setup:prod    # 스키마만 (시드 없음)
npm run build
```

터미널 두 개로 띄웁니다.

```bash
# 웹 — 기본은 루프백 바인딩
npm start -- -H 127.0.0.1 -p 4001

# 워커 + 게이트웨이 (watch 모드가 아닌 prod 스크립트)
npm run worker:prod
```

<http://localhost:4001> 접속 → **로그인 없이 바로 대시보드**가 뜹니다. **계정** 화면 → *계정 연결* → 전화번호 → 문자로 온 코드 (2단계 인증이 있으면 비밀번호까지). 기존 StringSession 이 있다면 *세션 문자열 붙여넣기* 로 바로 등록할 수 있습니다.

### 로그인이 없다는 것의 의미

이 앱에는 인증이 없습니다. **웹 포트에 닿을 수 있는 사람은 누구나 연결된 텔레그램 계정의 개인 대화를 읽고, 그 계정으로 메시지를 보낼 수 있습니다.** 그래서 기본 바인딩이 `127.0.0.1` 입니다.

원격에서 쓰시려면 둘 중 하나를 택하세요.

```bash
# 권장 — SSH 터널. 포트를 아예 열지 않습니다.
ssh -L 4001:127.0.0.1:4001 user@서버
# 그다음 로컬 브라우저에서 http://localhost:4001
```

```bash
# 또는 포트를 열되 내 IP 에서만 — 방화벽을 먼저 잠근 뒤에
sudo ufw allow from <내-IP> to any port 4001
WEB_HOST=0.0.0.0 pm2 start ecosystem.config.cjs
```

`WEB_HOST=0.0.0.0` 을 방화벽 없이 쓰는 것은 텔레그램 계정을 공개하는 것과 같습니다.

### pm2 로 상시 구동

`ecosystem.config.cjs` 가 들어 있습니다. **빌드를 먼저** 해야 합니다.

```bash
npm run deploy    # 빌드 + pm2 startOrReload — 코드를 받을 때마다 이것만
```

손으로 하시려면:

```bash
npm run build     # 필수. next start 는 빌드 결과물을 실행합니다
pm2 start ecosystem.config.cjs

pm2 list          # 상태
pm2 logs          # 두 프로세스 로그 함께
pm2 save && pm2 startup   # 재부팅 후 자동 시작
```

**빌드를 빼먹으면** `tg-web` 이 "Could not find a production build" 로 죽습니다. 설정 파일이 시작 전에 경고를 찍고, 다섯 번 시도한 뒤 `errored` 로 멈춥니다 (로그를 무한히 채우지 않습니다). `tg-worker` 는 영향 없이 계속 돕니다.

포트·바인딩을 바꾸려면 `WEB_PORT=5000 WEB_HOST=0.0.0.0 pm2 start ecosystem.config.cjs` 처럼 넘깁니다. pm2 는 이 설정 파일을 프로세스보다 먼저 읽으므로 이 둘만은 `.env` 가 아니라 셸에서 줘야 합니다.

두 프로세스 모두 `.env` 를 스스로 읽으므로 pm2 설정에 비밀값을 적을 필요가 없습니다 — Next 는 기본 동작이고, 워커는 `src/worker/loadEnv.ts` 가 가장 먼저 로드합니다.

> **`tg-worker` 는 절대 인스턴스를 늘리지 마세요.** 텔레그램 세션을 독점 소유하는 프로세스라, 두 개가 뜨면 계정마다 업데이트 스트림이 갈라지고 읽음 처리가 깨집니다. 게이트웨이 포트도 겹칩니다. `tg-web` 도 SQLite 잠금 때문에 fork 1개로 두었습니다.

### 실전에서 꼭 지킬 것

- **`SESSION_SECRET` 은 한 번 정하면 바꾸지 마세요.** 저장된 텔레그램 세션이 전부 복호화 불가가 되어 모든 계정을 다시 연결해야 합니다.
- **`prisma/dev.db` 를 백업하세요.** 세션·입장 기록·수집 링크가 전부 이 파일 하나에 들어 있습니다.
- **게이트웨이는 127.0.0.1 에만 바인딩됩니다.** 외부에 노출하지 마세요 — 소유권 검사는 웹 쪽에서 하므로, 게이트웨이가 열리면 그 검사를 건너뛸 수 있습니다.
- **웹 포트를 열어두지 마세요.** 인증이 없으므로 포트에 닿는 것이 곧 계정 접근입니다. 기본값인 루프백 + SSH 터널을 권합니다.
- **계정은 한 번에 하나씩 늘리세요.** 새 계정은 위험도가 높게 잡히고(`신규 계정`), 며칠 지나야 안정됩니다.

### 세션은 한 프로세스만 소유합니다

같은 계정으로 MTProto 연결을 두 개 띄우면 업데이트가 갈라지고 읽음 처리가 새기 때문에, **텔레그램 세션은 워커 프로세스만** 들고 있습니다. 워커 안에서 게이트웨이(HTTP, 루프백 전용)가 돌고, 웹은 그것을 통해서만 텔레그램에 접근합니다.

```
[브라우저] ──HTTP/SSE──▶ [Next.js] ──RPC──▶ [게이트웨이 = 워커] ──MTProto──▶ 텔레그램
                             │                      │
                             └────── SQLite ────────┘
```

계정 로그인만 예외입니다 — 코드·2FA를 주고받는 대화형이라 웹이 직접 처리하고, 끝나면 세션 문자열만 암호화해 저장합니다.

**소유권 검사는 웹 쪽에서 합니다.** 게이트웨이는 공유 비밀만 확인하므로, "이 계정이 이 소유자 것인가"는 `callGateway()` 가 매 호출마다 검사합니다. 소유자가 하나뿐이라 지금은 형식적이지만, 나중에 로그인을 다시 넣더라도 스키마와 질의를 그대로 쓸 수 있게 남겨 두었습니다.

### 한 번의 틱

```
계정마다:
  대기 중인가?         → 건너뜀 (재개 시각이 지나면 자동 해제)
  간격이 찼는가?        → 아니면 건너뜀
  일일 한도를 넘었나?    → 넘었으면 건너뜀
  → 다음 작업 1건 실행 (선행 채널이 우선순위 앞)
그다음:
  방 몇 개 순회 수집 → 미확인 링크 실체 확인 → 채점 → 기준 넘으면 자동 등록
```

계정 안에서는 철저히 순차, 계정끼리는 병렬입니다.

### 오류를 다루는 방식

| 상황 | 처리 |
| --- | --- |
| `FLOOD_WAIT` | 계정 전체를 요구된 시간만큼 정지. 작업은 그 시각으로 재예약되고 시도 횟수는 늘지 않음 |
| 이미 참여 중 / 승인 대기 | 실패가 아님 — 각각 `SUCCESS`, `WAITING_APPROVAL` 로 기록 |
| 링크 만료·비공개·차단 | 영구 실패로 즉시 중단 |
| 네트워크·분류 불가 | 30초 → 2분 → 10분 백오프 후 재시도, 3회 초과 시 실패 |
| 세션 만료 | 계정을 `NEEDS_CHECK` 로 두고 재연결을 요구 |

## 안전장치

이 도구는 남의 방에 계정을 밀어 넣는 일을 하므로, 기본값은 전부 보수적으로 잡혀 있습니다.

- **입장 간격 기본 20초.** 5초 미만은 입력 자체가 거부됩니다.
- **대기 요구는 그대로 따릅니다.** 우회하거나 다른 계정으로 같은 방을 다시 두드리지 않습니다.
- **말 걸기는 방마다 한 번.** 보낸 메시지는 즉시 삭제합니다. 기본값은 꺼져 있습니다.
- **연쇄 수집의 유일한 제동장치는 하루 등록 한도**입니다. 켜기 전에 한도를 낮게 잡으세요.
- **세션 문자열은 암호화 저장**됩니다. `SESSION_SECRET` 을 바꾸면 기존 세션은 복호화되지 않습니다.
- **스팸 제한이 감지되면 그 계정은 자동으로 멈춥니다** (`NEEDS_CHECK`). 제한 상태로 계속 입장하면 더 나빠집니다.
- **채팅은 개인 대화를 다 읽습니다.** 인증이 없으므로 포트 노출 = 대화 노출입니다.
- **메시지는 전부 저장하지 않습니다.** 연 대화와 키워드 적중분만 보관합니다.

## 개발

```bash
npm run test        # 링크 파싱·채점·선행 채널 인식 단위 테스트
npm run typecheck
npm run worker:once # 틱 한 번만 실행 (cron 이나 디버깅용)
npm run db:studio   # Prisma Studio 로 DB 열기
```

기본 DB 는 SQLite (`prisma/dev.db`) 입니다. Postgres 로 옮기려면 `prisma/schema.prisma` 의 `datasource` 를 바꾸고 `prisma db push` 를 다시 실행하면 됩니다. 스키마는 SQLite 에 맞춰 열거형 대신 문자열, 배열 대신 쉼표 구분 문자열을 씁니다 (허용값은 `src/lib/enums.ts`).
